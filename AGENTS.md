# AI Agents Collaboration Plan: Minimalist macOS MuPDF Reader

This document outlines the development plan for building a highly optimized, single-page, minimalist PDF reader for Apple Silicon (macOS) utilizing Swift and the MuPDF C library. The goal is to recreate a "SumatraPDF-like" experience on macOS with an ultra-low memory footprint (~30MB).

## Core Requirements & Features
- **Native Apple Silicon:** No Rosetta/Intel bloat.
- **Engine:** `libmupdf` (C library) bridged to Swift.
- **Memory Model:** Single-page buffer only. Old pages are immediately discarded from memory upon turning. Target RAM usage: ~25-45 MB.
- **UI:** Barebones AppKit window (no sidebars, ribbons, or standard PDFKit GUI).
- **Features (MVP):**
  - Open PDF files.
  - Instant page flipping (Single page view, no continuous scrolling).
  - Keybindings: Arrow keys and Vim bindings (`j`/`k`, `h`/`l`).
  - Zoom In / Zoom Out.
  - Dark Mode (color matrix inversion).
- **Explicitly Excluded (For Now):** Continuous vertical scrolling, Table of Contents / Outlines, text selection, search.

## Agent Roles & Task Breakdown

To build this application iteratively, the tasks are divided among specialized AI agent personas.

### 1. 🛠️ Agent 1: The Build System & Environment Architect
**Goal:** Setup the macOS project, Homebrew dependencies, and the C-to-Swift bridging header.

*   **Task 1.1: Dependency Management:** Ensure `mupdf` is installed via Homebrew (`brew install mupdf`) and retrieve the exact paths for headers (`/opt/homebrew/include`) and static libraries (`/opt/homebrew/lib`).
*   **Task 1.2: Xcode Project Setup:** Generate the required Xcode `.xcodeproj` structure or a Swift Package Manager (SPM) `Package.swift` that correctly links `libmupdf`, `libfreetype`, and `libharfbuzz`.
*   **Task 1.3: Bridging Header:** Write the `MuPDF-Bridging-Header.h` to expose MuPDF's C structures (`fz_context`, `fz_document`, `fz_page`, `fz_pixmap`) to Swift.

### 2. 🧠 Agent 2: The Core Engine (C-Swift Interop) Developer
**Goal:** Wrap the MuPDF C API in a safe, memory-leak-free Swift class.

*   **Task 2.1: Context & Document Management:** Create a Swift class `MuPDFDocument`. Implement initialization (`fz_new_context`), opening a document (`fz_open_document`), and safe teardown using Swift's `deinit` to call `fz_drop_document` and `fz_drop_context`.
*   **Task 2.2: Page Rendering (The Core Logic):** Write a method `renderPage(pageNumber: Int, zoom: Float, darkMode: Bool) -> CGImage?`.
    *   Load the page (`fz_load_page`).
    *   Apply scaling matrix (`fz_scale`).
    *   Render to a pixmap (`fz_new_pixmap_from_page_number`).
    *   Convert the raw RGBA bytes into a `CGDataProvider` and construct a native macOS `CGImage`.
    *   **Crucial:** Ensure `fz_drop_pixmap` and `fz_drop_page` are called immediately after the `CGImage` is created to enforce the 30MB memory profile limit.
*   **Task 2.3: Dark Mode Implementation:** Implement dark mode by modifying the MuPDF color space or applying an inversion matrix during the pixmap rendering phase.

### 3. 🖥️ Agent 3: The AppKit UI & UX Engineer
**Goal:** Create the minimalist macOS window, image view, and handle user input.

*   **Task 3.1: The Viewport:** Create a borderless or minimalist `NSWindow` containing an `NSImageView`. The image view will display the `CGImage` generated by Agent 2.
*   **Task 3.2: Keyboard Event Handling:** Override `keyDown(with event: NSEvent)` to listen for:
    *   `Right Arrow` / `l` / `j` / `Space`: Trigger Next Page.
    *   `Left Arrow` / `h` / `k`: Trigger Previous Page.
    *   `+` / `=`: Trigger Zoom In (increase scale factor and re-render).
    *   `-`: Trigger Zoom Out (decrease scale factor and re-render).
    *   `i`: Toggle Dark Mode state and re-render the current page.
*   **Task 3.3: Retina Display Optimization:** Detect the screen's backing scale factor (`NSScreen.main?.backingScaleFactor`). Pass this scale to Agent 2's render method so the PDF renders crisply at 2x resolution, while the `NSImageView` constrains it to logical points.
*   **Task 3.4: Jump to Page (`Cmd + G`):**
    *   Listen for the `Cmd + G` keystroke in the main window.
    *   When triggered, present a small, native macOS `NSTextField` overlay (similar to Spotlight's search bar) centered at the top of the window.
    *   Accept an integer input, validate it against `fz_count_pages`, immediately pass the new page number to Agent 2 to render, and dismiss the input box.
*   **Task 3.5: Discoverable Shortcuts & Hardware Guide:**
    *   Design a clean, visually appealing overlay (using a translucent `NSVisualEffectView` and centered text) to act as the "Key Binds & Guide" page. It must list all hotkeys and briefly explain NanoPDF's single-page, low-RAM philosophy.
    *   **Trigger 1 (Native Menu):** Add a standard "NanoPDF Shortcuts" clickable item in the macOS Menu Bar under "Help".
    *   **Trigger 2 (Floating UI):** Add a subtle, semi-transparent `NSButton` with a help icon (e.g., `questionmark.circle`) pinned to the bottom-right corner of the window.
    *   **Trigger 3 (Hotkey):** Bind the `?` key to quickly toggle this view on and off for keyboard-heavy users.

*   ### 4. 🕵️ Agent 4: The Profiling & QA Specialist
**Goal:** Ensure the app adheres to the strict performance and memory requirements.

*   **Task 4.1: Memory Auditing:** Use Xcode Instruments (Allocations & Leaks) to verify that turning a page frees the previous `CGImage` and MuPDF pixmap. The memory graph must remain flat (~30MB).
*   **Task 4.2: CPU & Threading:** Ensure that page rendering occurs on a background `DispatchQueue` to prevent the UI thread from hanging during page turns, smoothly transitioning the `CGImage` back to the main thread for display.

1.  *"Act as Agent 1. Here is my setup... generate the Package.swift and bridging header."*
2.  *"Act as Agent 2. The bridge is working. Write the Swift class to load a page into a CGImage without leaking memory."*
3.  *"Act as Agent 3. The engine works. Write the AppKit ViewController to display the image and handle Vim keystrokes."*
